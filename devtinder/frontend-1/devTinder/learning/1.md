In **React Router**, both `Link` and `useNavigate` are used to **change pages without reloading the browser** (client-side navigation).

### 🧭 Big picture (simple)

* **`Link`** → for **UI navigation** (user clicks)
* **`useNavigate`** → for **logic-based navigation** (after login, submit, timeout, etc.)

## 🔗 `Link`

Used **inside JSX** to create clickable navigation.

**Think:** “User clicks → go to page”

```jsx
import { Link } from "react-router-dom";

<Link to="/login">Login</Link>
```

✅ Why use `Link`?

* No page reload
* Faster than `<a href>`
* Keeps SPA behavior

❌ Don’t use:

```html
<a href="/login">Login</a>  // causes full reload
```

---

## 🧠 `useNavigate`

Used **inside component logic** to navigate **programmatically**.

**Think:** “Some condition happens → go to page”

```jsx
import { useNavigate } from "react-router-dom";

const Login = () => {
  const navigate = useNavigate();

  const handleLogin = () => {
    // after successful login
    navigate("/dashboard");
  };

  return <button onClick={handleLogin}>Login</button>;
};
```

### Common real uses

* After login / logout
* After form submit
* Redirect if user not authenticated
* Go back

```jsx
navigate(-1); // go back
navigate(1);  // go forward
```

## ⚔️ Quick Comparison

| Feature           | Link | useNavigate |
| ----------------- | ---- | ----------- |
| Used in JSX       | ✅    | ❌           |
| Used in logic     | ❌    | ✅           |
| On click          | ✅    | ❌           |
| After API success | ❌    | ✅           |
| Causes reload     | ❌    | ❌           |

👉 **Rule to remember:**

* **Click → `Link`**
* **Logic → `useNavigate`**

### 🧠 **Context Switching**

**Simple meaning:**
When the CPU stops one process and starts another.

**Why it matters:**

* Enables multitasking
* Has overhead (saving/restoring state)

**Interview line:**

> Context switching allows multiple processes to share the CPU but introduces performance overhead.
